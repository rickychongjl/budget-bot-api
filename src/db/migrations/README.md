# Migrations

Generated by `npm run db:generate` from `src/db/schema/*.ts`. **Forward-only — no
down migrations** (M1 §5). The committed SQL is the source of truth.

M1 owned no tables. `0000_identity.sql` (M2) is the first real migration —
`app_user` + `channel_connection`. The M3/M4 pair coordinate the migration that
carries their cross-FK tables (`category` ↔ `budget`, `transaction` ↔
`budget_period`) — see master plan §4.

Flow:
1. A module edits its own `src/db/schema/<module>.ts` and the barrel `index.ts`.
2. `npm run db:generate` writes `NNNN_<name>.sql` + `meta/` here; commit both.
3. CI applies these to a throwaway Neon branch per PR (`npm run db:migrate`).
4. On merge to `main`, the deploy job runs `db:migrate` against production and must
   succeed before `wrangler deploy`.
